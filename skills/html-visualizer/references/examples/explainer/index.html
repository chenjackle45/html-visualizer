Brewly 技術小學堂 · HTTP 快取

網頁沒變，為什麼能不再重傳

開啟 Brewly 豆款介紹頁時，瀏覽器能先問版本有沒有變。ETag 負責識別版本，304 告訴瀏覽器沿用已儲存的內容，省下重複下載。

01

一句話定義

兩個名詞，先各給一句話
版本標籤ETag
伺服器為內容版本附上的識別標籤，供之後的請求核對。
標籤由伺服器決定，不必是時間或雜湊。瀏覽器可連同內容保存，重新驗證時放進 If-None-Match 請求標頭。
未修改回應304 Not Modified
一種不帶內容本體的回應，表示條件符合、可以沿用快取。
在條件式 GET 或 HEAD 中，版本符合時伺服器可回 304。瀏覽器更新快取中繼資料，再使用原本保存的內容。
首次取得內容
200 OK
回傳內容本體，也可附上 ETag
驗證後沒有變
304
不重傳內容，但仍有網路往返
快取仍然新鮮
直接用
依快取規則，可能不必送出請求
不懂會怎樣：看到 304 不代表載入失敗。分清直接使用新鮮快取、向伺服器驗證、重新下載內容，才知道流量省在哪一步。
02

類比

用你已經熟的東西對照，細節等下一段
這套機制就像 咖啡豆目錄的版次與核對回覆
手上留有一份豆款目錄與版次↔本機內容
詢問時先報手上的目錄版次↔If-None-Match 條件
版次相同，回「沿用那份」↔304：內容未變
版次改變，寄來新版完整目錄↔200：傳送新內容
類比在哪裡失準：紙本版次通常按數字遞增，ETag 卻是不可自行推算的標籤；同一網址也可能因語言或壓縮方式而有不同版本，不能只看網址就認定是同一份內容。
03

核心模型

誰保存內容、誰帶條件、誰判斷版本是否相同

快取驗證分成哪些責任

瀏覽器 保存回應內容、ETag 與新鮮度資訊 前端
HTTP 快取層 判斷能否直接重用，必要時發出條件式請求 機制主場
來源伺服器 比對目前版本與 If-None-Match，選擇 200 或 304 後端
內容來源 提供豆款介紹的目前內容與版本依據 版本依據
ETag不決定快取能存多久，它只協助核對版本。是否可直接重用、何時需要驗證，由 Cache-Control 等快取規則決定。

快取需要驗證時，誰跟誰講話

瀏覽器
HTTP 快取層
來源伺服器
①→請求 Brewly 豆款介紹頁
②發現本機快取已過新鮮期
③←取出已保存的內容與 ETag
④→請快取層驗證已保存的版本
⑤→帶 If-None-Match 查目前版本
⑥←版本相同，收到 304 與回應標頭
⑦→更新快取資訊、使用已存內容

這裡畫的是版本未變的路徑。若版本已變，伺服器回 200 與新內容，瀏覽器便更新本機快取。

05

常見誤解

這三個是踩最多次的
常見的理解
「304 是錯誤，所以必須重新下載整頁。」
實際上
304表示條件式驗證通過。它沒有內容本體，瀏覽器使用已保存的內容，並依回應標頭更新快取資訊。
常見的理解
「有 ETag，就能永久直接用快取。」
實際上
ETag 只用來核對內容版本。新鮮期與重用限制由快取規則決定；需要驗證時，即使有標籤也仍要連線。
常見的理解
「304 不帶內容，所以完全沒有網路成本。」
實際上
304 仍然需要請求與回應的網路往返，只是省下內容本體。新鮮快取若可直接重用，才可能連驗證請求都省掉。
06

邊界

知道邊界比知道機制重要——不然會套到不該套的地方
!
沒有可用的本機副本 304 不附內容本體；快取遭清除或副本不可用時，不能只靠版本標籤畫出頁面，必須重新取得內容。
!
個人資料與共享快取 Brewly 的訂閱帳單與公開豆款頁不同。個人回應要依需求使用 private 或 no-store；ETag 本身不提供存取權限。
!
同網址有不同回應版本 語言與壓縮方式可能改變回應內容。伺服器需正確設定 Vary 與對應標籤，避免把不同版本當成同一份快取。
!
離線時無法取得 304 驗證需要連線；離線時能否使用過期副本要看快取規則與應用設計，不能假設一定可以沿用。
07

想更深入

主線到上一段就完整了；以下是原理與邊界案例
強 ETag 與弱 ETag 的差別 版本

強標籤要求對應的表示資料逐位元相同；弱標籤以 W/ 開頭，表示伺服器認為內容語意等價，但不保證每個位元都相同。

If-None-Match 使用弱比較，因此弱標籤也能用於 GET 的快取驗證。範圍請求與其他前置條件有不同規則，不能一概套用。

no-cache 與 no-store 是同一件事嗎 原理

no-cache 允許儲存，但每次重用前都必須向來源成功驗證；若版本沒變，就可能收到 304。這個名字並不是「完全不能保存」的意思。

no-store 則要求快取不要儲存該請求或回應。這與 private 的「不得存入共享快取」也不同，選用時先確認資料用途。

新鮮期該設多久，如何查標準 實務

沒有所有頁面通用的數字。公開豆款介紹可以容忍短暫延遲，庫存與個人帳單則要另外評估；本頁的 10 分鐘只是虛構示範。

延伸閱讀可查 RFC 9110 的 ETag、If-None-Match 與 304，以及 RFC 9111 的新鮮度與驗證章節；兩份分別規範 HTTP 語意與快取行為。
