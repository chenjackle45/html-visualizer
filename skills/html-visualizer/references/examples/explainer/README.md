# Example · 解釋型範本（教學 / 概念解釋 / 純資訊呈現）

> **沒有待拍板選項、純粹要讓人看懂一件事**時用這份。有拍板題請走 `marathon-decision-sheet/`。

## 為什麼需要這份

決策簿有明確的內容骨架（前情提要 → 架構變化 → 設計決策 → 失敗處理 → 數據佐證 → 拍板），純展示路徑過去**只有視覺參考、沒有內容骨架**——每次都在重新發明「該按什麼順序講」，所以品質靠當下手感、不穩定。

這份補的就是那個骨架。**骨架決定講的順序，元件決定每段長什麼樣**（元件見 `../../component-library.md` § 解釋類）。

---

## 骨架 A · 概念解釋型

「教我這個東西怎麼運作」「解釋這段機制」「這個設計為什麼這樣做」。

```
01 一句話 + 為什麼你該在意
     這是什麼（一句話，不用其他術語）＋ 不懂會怎樣
     ↓ 讀者現在有了錨點
02 類比橋
     用你已經熟的東西對照 ＋ 明講類比在哪裡失準
     ↓ 讀者有了粗略心智模型
03 核心模型一張圖
     由哪些部分組成、怎麼串起來（分層剖面 或 時序圖，二選一）
     ↓ 粗略模型換成正確結構
04 跟著一個真實例子走一遍
     同一份資料在每一步長什麼樣（狀態演進）
     ↓ 結構掛上了具體經驗
05 常見誤解
     你以為 X、其實 Y（至少一組）
     ↓ 修掉最容易走偏的地方
06 邊界
     什麼時候不適用、什麼時候會壞
     ↓ 防止把剛學到的東西過度外推
07 想更深入（收合）
     原理、推導、邊界案例、延伸閱讀
```

### 為什麼是這個順序

| 安排 | 理由 |
|---|---|
| 定義在類比**之前** | 沒有錨點時類比會漂——讀者不知道你在類比什麼。先用一句話立錨，類比才有對象 |
| 類比在機制**之前** | 先粗後細。直接進機制，讀者會在細節裡迷路且不知道自己在讀什麼 |
| 例子在模型**之後** | 先給結構、實例才有掛靠點。反過來會變成「看得懂每一步、但拼不出全貌」 |
| 誤解破解**靠後** | 要先有正確模型，才對照得出哪裡走偏。太早講誤解，讀者會把誤解記成正解 |
| 邊界在收合**之前** | 邊界是主線的一部分（不能收合）——不講邊界，讀者會把剛學到的東西套到不適用的地方 |
| 深入細節**收合** | 兩種深度的讀者各取所需，見 `../../interaction-patterns.md` § 漸進揭露 |

### 可以省略的段落

**02 類比**——概念本身就很具體時（例如「這個按鈕改成什麼行為」）硬做類比反而囉嗦。
**05 誤解**——真的想不到常見誤解就不要硬湊；但先問自己「是想不到，還是沒去想」。

**不可省略**：01（沒有錨點讀者不知道在讀什麼）、03（沒有模型就只是一堆句子）、06（沒有邊界會被過度外推）。

## 骨架 B · 資訊呈現型

「整理這批結果給我看」「盤點報告」「健檢結論」「進度回報」。

```
01 結論先講
     一句話 + 最關鍵的那個數字。不要讓人讀到第三段才知道結果
02 全貌地圖
     有哪幾塊、彼此什麼關係、這次涵蓋到哪（沒涵蓋的也講）
03 逐塊展開
     每塊固定三件事：是什麼 → 現況 → 值得注意的點
04 交叉切面
     換一個維度重看同一批資料（依嚴重度 / 依時間 / 依負責範圍）
     ⚠️ 同一份資料用同一種視覺呈現兩次會讓人疲勞，切面要真的換角度
05 待觀察 / 沒查到的
     還不確定的、查不到的、需要之後回頭看的。誠實列出比假裝完整有用
06 附錄（收合）
     原始數據、方法、逐項清單
```

兩種骨架**共用**：開場 30 秒內要能回答「這是什麼、與我何干」；每段至少一個視覺元件；細節收合。

---

## 必含元素

1. **Session 識別**（見 `../../session-identity.md`）— 多視窗並行時分辨來源
2. **頂部導覽**（TOC pills 或側欄）— 超過 4 段就要有
3. **每段至少一個視覺元件** — 純文字段落是訊號，不是常態
4. **至少一個解釋類元件** — 定義卡 / 類比橋 / 分層剖面 / 時序圖，看內容性質挑
5. **漸進揭露** — 細節收合，主線保持可讀
6. **邊界段** — 「什麼時候不適用」，骨架 A 的 06 或骨架 B 的 05
7. **Anthropic 風視覺** — token 見 `../../color-and-typography.md`

## 自我檢查（open 前必跑）

```bash
python3 <本 skill 目錄>/scripts/verify.py <file>
```

純展示類會跑：結構完整性、Session 識別已填值、**每段都有視覺元件**、長文件有漸進揭露、中英混雜詞。

指令**判斷不了骨架順序**——它只列出段落 id，你要自己對照上面的骨架 A / B。缺這幾段即違規：骨架 A 的「一句話定義 / 核心模型 / 邊界」、骨架 B 的「結論先講 / 待觀察」。

「每段都有視覺元件」是最常被跳過、也最影響體感的一項——**「有寫」跟「看得懂」是兩件事**。

## 嚴格禁止

- **沒有邊界段** — 讀者會把剛學到的東西套到不適用的地方，比沒學更糟
- **類比沒標失準處** — 沒標的類比會被無限外推，產生比不解釋更糟的誤解
- **把關鍵資訊收進漸進揭露** — 收合區只放原理與邊界案例，主線讀完就該能用
- **用樹狀元件畫分層架構** — 樹狀是分類與分支、分層是堆疊與相依，兩者不能互換
- **交叉切面用跟前面一樣的視覺** — 同一份資料同一種呈現兩次＝疲勞，切面要真的換角度
- **純文字段落** — 自檢指令會直接點出是哪一段
