# Example · 編輯風報告（骨架 B ＋ 少量拍板題）

> **報告／盤點／健檢結論／研究結果**都從這份起手：夾 1–4 題拍板就照原樣用；沒有拍板題照下面「無拍板題時怎麼裁」刪。內容順序照 `explainer/` 的骨架 B。拍板題 ≥ 5 題走 `marathon-decision-sheet/`；教學、概念解釋走 `explainer/` 骨架 A。

## 這份從哪來

一份真實報告頁經四輪獨立評審（Awwwards 四項：設計、可用性、創意、內容）迭代到四項 8 分，再去識別化成本範例：內容全部換成示例（數字、對話、團隊都是虛構的），版面、元件、互動照留。每一處設計都是評審扣過分、改了才過的地方，做法拆成元件收在 `../../component-library.md` §「編輯報告類」。

## 何時用

| 情境 | 用哪份 |
|---|---|
| 報告／盤點結論，沒有拍板題 | ⭐ 本範例，照「無拍板題時怎麼裁」刪；順序照 `explainer/` 骨架 B |
| 教學／概念解釋 | `explainer/` 骨架 A |
| 報告／盤點結論，夾 1–4 題拍板 | ⭐ 本範例原樣 |
| 拍板題 ≥ 5 題、marathon 收尾 | `marathon-decision-sheet/` |
| 規格要跟非技術 stakeholder 對齊 | `spec-alignment/` |

## 骨架（骨架 B 的六段，拍板題就地放）

```
Hero      一個大數字 ＋ 一句主張 ＋ 證據等級圖例〔查〕〔轉〕〔推〕＋ 題目地圖（要拍的題，點了跳過去）
          首屏（1440×900）要露出 hero 的結論句與題目地圖；01 段的答案卡放第二屏可以。hero 高度不用為了擠答案卡再壓
01 結論先講   三張答案卡：問題 → 一句答案 → 補一兩行
02 全貌地圖   寬 SVG 結構圖＋探索層（點格看說明）；≤640px 換直式卡片清單
              量級對比三格大數字 ＋ 一句結論
03 逐塊展開   每塊一個 h3；拍板卡放在它的背景段末尾（Q1：對話現況 vs 改後樣張）
              表格 ≤640px 每列變一張卡
04 建議順序   步驟卡（第 0 步「已排、不用拍」也列出來）＋ Q2
05 待觀察     誠實列出不知道的事：原因、怎麼補
收束帶       深色：一句結論 ＋ 步驟小圖 ＋ 第二顆複製鈕（呼叫同一個摘要函式）
06 附錄（收合）證據清單、方法
底部列       一開始就顯示：「已選 N / M · 還差：<題名>」（點了跳到那題）＋「反白任何一段文字就能留言 · 已留 N 則」＋ 預覽、複製
             手機兩行、約 86px：上行留言提示，下行「已選 N / M · 下一題 →」＋「預覽」「複製摘要」（按鈕字縮短才放得下）
             預覽是從底部升起的抽屜（停在列上方、附「關閉預覽」），不在列內往上長
Hero 手機    ≤900px 單欄時排成：標籤 → 大「0」→ 它的說明 → 標題 → 引言 → 圖例 → 題目地圖。0 與說明是圖＋圖說，讀者不用先猜 0 是什麼
```

## 換內容時要動的地方

1. **文字**：照骨架逐段換。示例數字、示意對話全部換掉；`<title>` 一起改：拍板摘要的標題行直接取 `<title>`（`# <標題> · 拍板摘要`）。
2. **全貌地圖**：節點、線、標籤照 `../../structure-diagrams.md` §6 畫；每格說明寫在 `template[data-detail]`，手機版卡片（`.mcards`）的 `data-from` 指到同一個 id，內容由腳本複製過去，不用寫兩次。
3. **拍板題**：每張卡 `data-decision data-id`、radio 的 `name`、回傳列腳本 `// § buildFeedback 複製格式` 段裡的 `getValue("q…")` 三處要對上；題數改了，題號晶片的「共 N 題」、頂端 `#nav-prog` 的初始字（分母由腳本自動更新）、每張卡的 `data-title`（回傳列「還差：…」顯示的短題名，照題目地圖的字寫）、hero 題目地圖（`#qmap-list` 每題一個 `<a href="#dec-…" data-q="…">`，與「要你拍板 N 題」）一起改。補充框（`textarea.note`）一律常駐，不要改成收起或按鈕展開。
4. **表格**：每個 `<td>` 帶 `data-label`＝它那欄的表頭文字，手機版才有欄名。
5. **Session 識別**：`window.VT_SESSION` 照 SKILL.md 填。

## 無拍板題時怎麼裁

純報告（盤點、健檢、研究結論）沒有要拍的題時，從本範例起手、照下表刪。**HTML 與腳本要一起刪**：拍板摘要腳本一載入就對 `#preview-btn` 等按鈕掛監聽器，按鈕刪了腳本沒刪，`getElementById(...)` 拿到 null，整段腳本在載入時炸掉。

| 刪什麼 | 在哪裡 |
|---|---|
| 每一張拍板卡 | `<div class="card decide …" data-decision data-id="…">…</div>`（03、04 段各一張） |
| 底部拍板列 → 換成回傳列 | 不要整條刪：`<footer class="sticky-bar" data-tw-lock>…</footer>` 換成 `../../../assets/base-template.html` 的回傳列（搜「回傳列」，CSS、HTML、腳本三段照抄），讀者才有留言與「複製給 AI」的入口。footer 後面的預覽抽屜 `<div id="preview-area" …>` 也換成 base 那份（兩邊結構相同） |
| hero 的題目地圖 | `<nav class="qmap" …>…</nav>` |
| 章節列的拍板計數 | `<button … id="nav-prog">拍板 0 / 2</button>` |
| 收束帶的複製鈕 | `<button id="copy-btn-2" …>複製拍板摘要</button>`；步驟小圖裡的 `Q1／Q2` 標籤改成狀態字（例「待做」）或刪掉 |
| 其他地方的題號標籤 | 01 段答案卡的 `<span class="qb">Q1</span>`、04 段步驟卡的 `<span class="badge q">Q1</span>` |
| **回傳列腳本整段** | 以 `// 回傳列：留言數同步、拍板進度…` 開頭的那個 `<script>`：它是 base 回傳列腳本加上本頁的章節列計數、題目地圖、補充框長高、收束帶複製鈕。整段換成 base 的回傳列腳本（沒有拍板題時它只收留言）。抽屜裡的 `#vt-clear-picks`、`#preview-note` 跟著 base 的抽屜 HTML 走 |

**不要刪**：
- 以 `// 三段式：clipboard API` 開頭的腳本（`vtCopyText`、`vtSelectForManualCopy`）：全頁評論工具的複製也用它。
- 全頁評論 snippet、Session 識別、探索層腳本。
- 樣式不必刪；沒用到的規則不會出錯。

刪完跑 verify：「JS 參照的元素都存在」會列出還有腳本在找的 id，執行期健檢會抓到載入時的錯誤。換上回傳列之後，「風格設定」按鈕照樣停在「預覽」左邊；看 390px 首屏截圖確認列沒有被章節列蓋住。

## 刻意留著的做法（拿掉會退步）

| 做法 | 拿掉會怎樣 |
|---|---|
| hero 的題目地圖 | 本頁第一題在可見文字的 54% 處（verify 門檻 40%）。只想拍板的讀者靠題目地圖直接跳；拿掉它 verify 判不及格。選過的題會標「已選」 |
| radio 視覺隱藏（opacity:0＋absolute、`inset:0` 蓋滿整張選項格）、`.choice` 帶 `position:relative`、`:has(input:focus-visible)` 3px 外框 | 用 `display:none` 藏 radio，Tab 永遠落不到，鍵盤拍不了板（第 1 輪評審 HIGH）。少了 `position:relative`，absolute 的 radio 會定位到外層，Tab 時畫面捲到錯的位置。radio 只有 1px 時，瀏覽器只把那 1px 捲進畫面，較高的選項格邊緣會被固定列蓋住 |
| 預覽抽屜放在 `<footer>` 外面、`openPreview()` 設 `bottom` | 列有 `backdrop-filter`，放在列裡的 fixed 抽屜會被困在列的框裡。複製失敗的退路也走 `openPreview()`，抽屜才不會蓋住複製鈕 |
| `html body { line-height: 1.7 }` 與 `button, input… { line-height: inherit }` | 當初是為了蓋過 Tailwind CDN 的重置（它在本頁樣式之後插入，會把內文行高洗成 1.5）；2026-10-27 拿掉 CDN 後，這兩條決定本頁的行高，留著。拿掉前後 1440 與 390 截圖相同，只有回傳列「下一題 →」底線尾端 2 個像素的反鋸齒差異 |
| 底部列一開始就顯示 | 「反白任何一段文字就能留言」要讓讀者從第一屏就看到；原本等第一張拍板卡出現才滑出，讀前半頁的人不知道能留言。列的層級高於章節列（手機首屏章節列剛好停在列上方） |
| `--serif` 最前面的 `VTDigits` | Chrome 的標題字是 Georgia，數字變舊式字形，大數字「0」像小寫 o |
| `h1, h2, h3 { word-break: keep-all }` 加 `.ph` 片段 | 中文標題被切在詞中間（「三個答／案」）。h1、h2、h3 與收束帶那句用 `<span class="ph">` 包語意片段，換內容時照包 |
| 章節號只留浮水印 | eyebrow 只寫章名（「結論先講」），編號由章首右側的淡色大數字（`data-n`）與章節列帶；兩處都寫數字會重複 |
| 淡入是 fail-open | 只有被腳本加上 `rv-pre` 的區塊才會先透明；列印樣式與 `beforeprint` 一律顯示，捲動時一次跳過去的區塊也會補顯示。改成用樣式預設隱藏的話，列印、存 PDF 或腳本出錯時後半頁是空白 |
| 探索層浮窗藏掉追線按鈕、把手 | 非工程讀者只想讀那格說明；追線工具被評審判為「工程師工具露在讀者面前」 |

## 不要做

- 不要把拍板題集中到文件尾段——就地放，同 marathon 範本的配對規則。
- 不要把示例數字留在交付頁上；附錄的證據清單每列都要對到真實來源。
- 不要另寫一份摘要函式給收束帶的複製鈕。
